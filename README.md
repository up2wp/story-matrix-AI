# Story Matrix AI

AI 驱动的小说创作工具，帮助作者从灵感激发到成稿全流程高效创作。

## 创作流程

作品从零到成稿经历五个阶段，每个阶段可迭代回退：

```
故事萌芽 → 世界构建 → 主线大纲 → 核心约束 → 章节丰盈
```

1. **故事萌芽** — 用随机构建或灵感选择两种方式，快速确定时间、地域、类型、基调等基础信息，挑选初始主要人物
2. **世界构建** — AI 生成世界观设定，深化角色经历/性格/关系，自动补充非主要人物，实时检测一致性冲突
3. **主线大纲** — AI 生成起承转合的章节骨架，树状结构支持拖拽调整
4. **核心约束** — 定义关键事件、角色命运、伏笔回收等必要情节要素，作为章节生成的硬性约束
5. **章节丰盈** — 综合所有信息，逐场景生成正文草稿，支持续写、改写、对话生成等辅助模式

## 功能介绍

- **故事萌芽** — 随机构建 / 灵感选择，快速生成故事基础信息与候选人物
- **世界观构建** — 自动生成规则体系、地理政治、文化设定，支持关联引用与一致性检查
- **角色管理** — 主要人物深化 + 配角自动生成，经历/性格/关系/弧线全方位管理
- **大纲编辑器** — 树状结构（卷 > 章 > 节），支持拖拽排序与层级折叠
- **核心约束** — 五类约束（事件/命运/伏笔/红线/节奏），三级优先级，覆盖状态追踪
- **正文写作** — 沉浸式编辑器，场景提纲 + Markdown 格式 + 字数统计 + 专注模式
- **AI 辅助** — 基于上下文的续写、改写、扩写/缩写、风格迁移、对话生成
- **版本管理** — 章节级版本历史，支持对比与回滚
- **多线叙事** — 支持多视角、多时间线并行创作，矩阵式管理故事线
- **导出发布** — 导出为 TXT / EPUB / PDF，支持自定义排版模板
- **有声读物（Voicebox）** — 在声音管理中维护个人音色，在章节丰盈中为单章绑定旁白/角色音色并生成章节音频
- **视觉资产 / 生图工作台** — 管理员配置可用生图模型并授权用户，作者在作品上下文中生成、编辑、保存、复制视觉提示词，并通过后端代理生成图片

## 快速开始

### 1. 安装依赖

```bash
# 安装前端依赖
npm install

# 安装后端依赖
cd server && npm install && cd ..
```

### 2. 启动开发服务器

```bash
# 终端 1：启动后端
npm run dev:server

# 终端 2：启动前端
npm run dev
```

### 3. 访问应用

打开浏览器访问 `http://localhost:5173`

### 4. Docker 部署

也可以直接拉取已构建镜像并运行：

```bash
docker run -itd --name story-matrix-ai --restart always -p 3001:3001 -v story-matrix-data:/app/server/data ghcr.io/up2wp/story-matrix-ai:latest
```

<!-- docker run -itd --name story-matrix-ai --restart always -p 3001:3001 -v ~/docker/story-matrix-data:/app/server/data ghcr.io/up2wp/story-matrix-ai:latest -->

Docker 部署默认访问 `http://localhost:3001`。源码本地构建镜像部署的方法见 [Docker 部署手册](docs/docker-deploy.md)。

如果测试环境需要在局域网内通过 `http://服务器IP:3001` 访问，请用 `NODE_ENV=development` 启动容器，避免浏览器因 HTTP 访问拒收生产模式下的 `Secure` 登录 Cookie：

```bash
docker run -d --name story-matrix-ai \
  -e NODE_ENV=development \
  -p 3001:3001 \
  -v story-matrix-data:/app/server/data \
  ghcr.io/up2wp/story-matrix-ai:latest
```

正式公网部署建议使用 HTTPS 访问，并保留镜像默认的生产模式。

### 5. 默认账号

系统首次启动会自动创建管理员账号：

| 字段 | 值 |
|------|-----|
| 用户名 | `admin` |
| 密码 | `admin` |

> ⚠️ **安全提示**：首次登录后请立即修改默认密码。

### 6. 配置 AI 服务

登录后进入 **管理后台**，配置 AI 服务提供商：

| 提供商 | Base URL 示例 | 说明 |
|--------|---------------|------|
| OpenAI | `https://api.openai.com/v1` | 官方 API |
| vLLM | `http://192.168.1.100:8000/v1` | 本地部署 |
| Ollama | `http://localhost:11434/v1` | 本地部署 |

### 7. 配置 Voicebox 有声读物

如需生成有声读物，请先准备可访问的 Voicebox 服务，然后进入 **管理后台 → Voicebox** 配置服务地址。开发环境可使用默认地址 `http://127.0.0.1:17493`，生产环境应配置线上 Voicebox 域名，例如 `https://voicebox.example.com`。

Voicebox 请求始终由 Story Matrix AI 后端代理转发，浏览器不会直连 Voicebox，也不会持有 Voicebox 的鉴权凭据。管理后台支持以下鉴权方式：无鉴权、Bearer Token、`X-API-Key`、自定义 Header。

使用流程：

1. 在管理后台保存 Voicebox 地址和鉴权方式，并点击“检查连接 / 刷新音色”。
2. 在 **声音管理** 页面上传自己的参考音频和对应文本，上传前确认已拥有或获得该声音授权。
3. 在 **章节丰盈** 中打开已有正文的章节，在章节下方“有声读物”面板配置全局旁白音色和本章角色音色。
4. 为角色点击“AI 生成提示词”，检查包含 `【上下文】` 的 QwenTTS 朗读指导后保存；待朗读正文会单独传给 Voicebox `text`。
5. 点击“AI 分段”，系统会先用规则快速生成可编辑初稿，再对低置信度对白做小窗口 AI 归因；分段面板会显示批次进度、低置信度提示和失败片段可重试入口。检查并编辑说话人、文本和语气提示词后，先点击“保存修改”，再点击“生成章节音频”。一键生成语气默认不会覆盖已手写的提示词；音频生成、失败重试和合并分段都基于已保存版本运行。完成后可在线播放片段或下载章节级清单。

说明：Story Matrix AI 只保存 Voicebox profile/sample/generation ID、用户声音索引、角色语音提示词模板和章节分段脚本；参考音频与生成音频仍由 Voicebox 管理。当前版本以章节级生成为边界，不做整本拼接或发布级后期。修改旁白音色或旁白提示词会让所有章节音频失效，修改某章节角色音色或提示词只影响该章节相关片段。

### 8. 配置视觉资产 / 生图

如需在作品内生成角色和章节视觉资产，请先由拥有者或管理员进入 **管理后台 → 生图模型** 开启功能。配置时先添加生图厂商，再从厂商刷新或选择要启用的模型；同一厂商下多个模型共享 API 地址和 API Key，不需要重复填写连接信息。API 地址和 API Key 只保存在后端系统配置中，普通用户配置响应只会看到已启用模型的显示名称、厂商标签、尺寸/比例/质量/格式能力和参考图能力摘要。

使用流程：

1. 管理员添加生图厂商，选择 OpenAI Images、OpenAI 兼容、自定义端点或 MiniMax 中国，填写 API 地址和 API Key。MiniMax 中国默认使用 `https://api.minimaxi.com`，API Key 请使用自己的 `MINIMAX_API_KEY`。
2. 点击“刷新厂商模型”或使用厂商预设模型，选择要启用的模型，并设置“显示给作者的名称”。真实厂商模型通常由系统自动填入；需要手动添加时填写“厂商模型”，例如 MiniMax 的 `image-01` 或 `image-01-live`。
3. 在同一页面选择图片存储方式：默认本地存储；如启用 Immich，需填写 Immich 服务地址、API Key 和项目名称。项目名称会自动映射为 Immich 相册，系统会创建或复用同名相册。
4. 在 **系统设置 → 用户级功能权限** 中为普通用户授权“作品生图”。拥有者和管理员在全局开关开启后默认可用。
5. 作者打开作品后进入 **视觉资产**，先选择图片类型，再选择章节。高清头像和章节服饰共享同一份本章人物候选，下拉中包含本章出现的作品角色和未关联人物；章节服饰在选择人物后再选择该人物的明文服饰候选，也可选择固定“无描述”生成基础服饰素材；章节道具不需要选择角色，直接加载本章出现的道具候选。所有通过 AI 从章节提取加载的候选都会按章节缓存，并可用“刷新候选”重新提取；刷新后若原选择不再存在，页面会要求重新选择。未关联人物可用于当前画面生成，但不会自动写入作品角色库。用户可基于候选生成草稿或手写提示词。
6. 检查并保存提示词后选择已启用模型生成图片；多视角全身图可选择正面、侧面、背面方向，并在支持参考图的模型上选择当前作品中最多 3 张已成功生成的图片作为参考。失败时提示词、模型、方向和参考图选择会保留，可复制或重试。

V1 支持角色高清面部特写、章节服饰、章节道具、多视角全身图四类新建提示词；历史作品中的“章节服饰/道具”旧类型会继续展示和参与上下文引用。提示词默认面向后续一致性任务，生成纯白背景、主体清晰、可复用的设定素材，而不是复杂剧情插画。高清头像提示词会强调清晰五官和面部特征；服饰和道具提示词不会主动生成背景、色调、场景氛围或角色动作。视觉资产流程的章节候选抽取会拆成人物抽取、角色映射、道具抽取和服饰抽取，草稿生成由服务端根据作品数据和已选候选重建上下文，浏览器不会提交自由文本系统提示词、任务指令或完整上下文。视觉资产流程的章节候选抽取和草稿生成可由服务端读取完整章节，并发送给系统配置的文本 AI Provider 做视觉理解；浏览器请求、API 响应、作品 JSON、视觉资产缓存、提示词记录和图片记录只保存结构化短字段或用户可见提示词，不保存完整章节正文、长摘录、Provider API Key、真实 Provider URL 或整段 base64。

生成图片默认落到服务端受控资产目录；启用 Immich 后，系统会在调用生图 Provider 前先检查 Immich 服务可达、API Key 有效且具备上传能力，检查失败不会消耗生图额度。OpenAI Images / OpenAI 兼容厂商无参考图时继续使用 `/images/generations` 的 base64 响应，有参考图时由服务端走 `/images/edits`；MiniMax 中国使用 `/v1/image_generation` 并默认请求 base64，只有 `image-01` 的单张角色参考图路径会发送 `subject_reference`。参考图会由服务端读取图片 bytes 并发送给所选第三方生图 Provider，浏览器不会上传 provider 可直连 URL、base64 或本地文件路径。Immich 上传成功后，作品只保存 asset id、文件名、存储状态、方向/参考图 id 快照和同源后端代理地址；浏览器不会拿到 Immich 服务地址、Provider API Key、真实 Provider URL 或整段 base64，也不会直连 Immich 或生图厂商。生成成功但 Immich 上传失败时，服务端会自动重试，失败后保留可恢复状态供用户重试。作品 JSON 不保存上游临时 URL、API Key 或整段 base64。当前版本不做额度统计、人脸一致性评分、参考图权重调参、LoRA、自动挑图、批量重绘，也不会自动写入角色头像或章节插图。
